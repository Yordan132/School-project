# OnePlace · Универсална система за резервации

Учебен проект с **React + Vite, JavaScript и CSS**. Един общ модел за ресурси, интервали и капацитет обслужва три отдела. Има клиентски и администраторски панел, тъмен/светъл режим и адаптивен интерфейс.

## Стартиране във Visual Studio Code

Нужни са Git, VS Code и **Node.js 22.12+ (препоръчително Node 24 LTS)**.

```bash
git clone https://github.com/Yordan132/School-project.git
cd School-project
code .
npm install
npm run dev
```

Ако `code` не работи: VS Code → File → Open Folder → папката на проекта. Командите `npm` се изпълняват в Terminal → New Terminal. Отворете адреса от терминала, обикновено http://localhost:5173. За спиране: Ctrl+C.

При обновяване: `git pull`, `npm install`, `npm run dev`. Хранилището е частно и изисква GitHub достъп.

## Демо профили и панели

Изберете „Демо профил“ в горната част:

- **Алекс Иванов, Елица Петрова, Борис Георгиев:** клиентски профили. Всеки създава резервация за себе си и вижда/редактира/отменя само своите резервации във всички отдели и дати.
- **Администратор:** вижда всички клиенти (включително без резервации), техните резервации и брой резервации. Филтрира по клиент, вид услуга и дата, редактира и отменя. При хотелски филтър датата означава нощувка, а денят на напускане е изключен.

Клиентското име се попълва от активния профил и не може да се подменя във формата. `customerId` определя собственика. При смяна на профила незаписаната редакция се затваря. Заетостта винаги се изчислява от **всички** резервации, така че скритите чужди часове продължават да блокират ресурса.

**Това е демо разделяне на роли, не истинска защита.** Всеки, който отваря приложението, може да избере демо администратора. Данните и проверките са в браузъра. Реална автентикация изисква сървър, база данни, сесии и сървърни проверки. Не въвеждайте реални медицински или други чувствителни данни.

## Архитектура

```text
src/
  App.jsx                       активен профил, отдел, резервации и действия
  components/
    ReservationEditor.jsx       избор на ресурс и часове/нощувки
    BookingForm.jsx             обобщение и потвърждение
    BookingList.jsx             списък с резервации
    AdminPanel.jsx              всички клиенти и филтри
    SlotGrid.jsx                свободни начални часове
    ThemeToggle.jsx             тъмна/светла тема
  data/
    businesses.js               конфигурация на трите отдела
    profiles.js                 примерни клиентски и admin профили
    seed.js                     валидни примерни резервации
  utils/
    booking.js                  часови слотове, индекс и обща валидация
    hotels.js                   свободни стаи и валидация на престой
    suggestions.js             алтернативни часове, хотели и дати
    ids.js                      генериране на ID и при достъп през локалната мрежа
    access.js                   собственост и действия върху резервациите
    dates.js                    работа с календарни дати
    storage.js                  localStorage и проверка при зареждане
```

`App` държи данните в `useState`, предава props и функции на компонентите. `ReservationEditor` държи временните полета на формата. `saveReservation` проверява правото за редактиране, задава собственик и валидира наличността преди промяна. `cancelReservation` отново проверява собственика. Скриването на бутона не е единствената проверка.

## Интерфейс и теми

Дизайнът използва обикновен CSS в `src/styles.css`, разделен с коментари по части на екрана. Цветовете са CSS променливи в началото на файла; тъмната тема сменя стойностите им чрез `data-theme="dark"`. Няма допълнителна библиотека за интерфейса или външни шрифтове.

На компютър изборът на ресурс и наличност е до обобщението на резервацията. На телефон секциите се подреждат една под друга, а отделите са в горната навигация. В администраторския панел първо са филтрите и резервациите, след тях — клиентите. Промяна в тези стилове не променя алгоритмите в `utils/`.

## Модел на данните

Общи полета: `id`, `businessId`, `resourceId`, `customerId`, `customer`, `date`, `quantity`.

Часова резервация:

```js
{
  id: 'booking-1', businessId: 'clinic', resourceId: 'cardiologist',
  customerId: 'alex', customer: 'Алекс Иванов',
  date: '2026-12-07', start: 540, end: 570, quantity: 1
}
```

Хотелска резервация:

```js
{
  id: 'booking-2', businessId: 'hotels', resourceId: 'spa',
  customerId: 'alex', customer: 'Алекс Иванов',
  date: '2026-12-07', endDate: '2026-12-09',
  roomType: 'double', quantity: 2
}
```

В първия пример минутите 540–570 са 09:00–09:30. Вторият е две двойни стаи за две нощувки. Интервалите са `[начало, край)` — краят не е включен. При редакция собствената резервация се изключва от заетостта, а собственикът се запазва, включително когато редактира администраторът.

## Конфигурация и универсалност

Нов отдел или ресурс се добавя в `src/data/businesses.js`.

- `mode: 'hours'`: `step`, `durations`, `hours`, `resources`.
- `mode: 'nights'`: `resources` с общ капацитет и `roomTypes` с отделен капацитет; няма часови слотове.
- Всеки ресурс има уникален `id` в отдела, `name`, `detail`, положителен целочислен `capacity`.
- Отделът има уникален `id`, `name`, `type`, `icon`, `description`, `resourceLabel`.

За часовете: `step` е положително цяло число, което дели 1440. Начало, край и продължителности са кратни на стъпката. Работните интервали са подредени, без застъпване, в рамките 0–1440. Дните са 0 (неделя) до 6 (събота); липсващ ден е почивен. Нов отдел с тези правила използва същите компоненти и алгоритми.

## Оптимизация

- **Map индекс:** O(N) за N резервации. Ключът е отдел + ресурс + дата; при хотели датата в ключа е `*`, защото престоят пресича дни. Изборът получава само съответните k резервации.
- **Часове:** масив на разликите — добавяме количество при начало и изваждаме при край. Един обход дава заетост за T = 1440 / step клетки. Цена O(k + T). Всеки възможен начален час проверява максималната заетост за D клетки от продължителността: общо O(S × D) за S начала.
- **Нощувки:** събития „пристигане + количество“ и „напускане − количество“, изрязани до търсения период. Сортиране O(k log k) и един обход за максимална едновременна заетост. При еднаква дата първо освобождаваме стаите. Не събираме погрешно неприпокриващи се престои.
- **React:** `useMemo` за индекса, видимите резервации, заетостта и слотовете. `memo` за мрежата с часове. Формата има локално състояние. Изчислява се само избраният ресурс, не всички ресурси и бъдещи дати.

При запис общата валидация и обновяването на масива обхождат N записа; индексът и localStorage също се обновяват O(N). Началното валидиране може да е O(N²) или по-скъпо при много хотелски записи заради сортирането. Това е компромис за разбираем учебен код, не система за неограничено количество данни. За реално натоварване: сървър, индексирана база, странициране и транзакции.

## Запазване и съвместимост

`myasto-bookings-v2` пази резервациите, `myasto-profile` — избрания демо профил, `myasto-theme` — темата. По-старите хотелски резервации във v2 без зададен вид стая се запазват и временно намаляват наличността на всички видове стаи; при редакция се избира конкретен вид. Старите данни във `myasto-bookings-v1` остават непокътнати; не ги приписваме автоматично на клиент, защото липсва собственик и отделите са променени. Показва се съобщение и новата версия започва с примерни данни.

„Възстанови примерните данни“ е само в администраторския панел и изисква потвърждение. Данните не се синхронизират между устройства или раздели. За демонстрацията са разрешени и минали дати. Темата започва тъмна и може да се превключи от горната лента.
