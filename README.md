# Място · Универсална система за резервации

Учебен проект с **React + Vite, JavaScript и CSS**. Общият механизъм за резервации се настройва чрез конфигурация. Включени са салон, медицински кабинет и спортни зали. Интерфейсът е на български и работи на телефон и компютър.

## Стартиране във Visual Studio Code

Необходими са Git, Visual Studio Code и **Node.js 22.12+ (препоръчително Node 24 LTS)**.

1. В терминал изпълнете:

   ```bash
   git clone https://github.com/Yordan132/School-project.git
   cd School-project
   code .
   ```

   Ако `code` не е достъпно, отворете VS Code → File → Open Folder → папката `School-project`.
2. Във VS Code отворете Terminal → New Terminal:

   ```bash
   npm install
   npm run dev
   ```
3. Отворете адреса, изписан в терминала (обикновено http://localhost:5173).
4. За спиране натиснете Ctrl+C. При следващо стартиране е достатъчно `npm run dev`.

Хранилището е частно: за клониране трябва да сте влезли с GitHub профил с достъп. За обновяване на вече клонирано копие използвайте `git pull`, след това `npm install`.

## Какво може приложението

- Превключва между бизнеси с различни ресурси, работно време, почивки, стъпка и продължителности.
- Филтрира по дата, ресурс, продължителност, брой места и свободни часове.
- Създава, редактира (включително дата и ресурс) и отменя резервации.
- Проверява едновременно заетия капацитет през целия интервал.
- Запазва данните в localStorage и възстановява примерните данни след потвърждение.
- Показва грешки при невалидни или недостъпни запазени данни.

За демонстрацията може да се избира и минала дата. Примерните резервации се генерират за текущия ден само за работещите бизнеси.

## Структура и поток на данните

```text
src/
  App.jsx                 състояние, филтри и действия
  components/
    SlotGrid.jsx          свободни и заети начални часове
    BookingForm.jsx       данни на клиента и потвърждение
    BookingList.jsx       резервации за избрания бизнес и ден
  data/
    businesses.js         конфигурациите на бизнесите
    seed.js               примерни резервации
  utils/
    booking.js            чисти функции за наличност и валидация
    storage.js            зареждане и запис в браузъра
  styles.css              адаптивен дизайн
```

`App` държи резервациите и избраните филтри в `useState`. Компонентите получават данни чрез props и изпращат действия чрез функции. При запис първо се проверяват данните, след това се обновява масивът, а `useEffect` го запазва. Формата държи името локално, затова писането в нея не преизчислява графика.

## Общ модел

Ресурс е всичко, което може да бъде резервирано: човек, кабинет, маса, зала или оборудване.

```js
{
  id: 'unique-id',
  businessId: 'studio',
  resourceId: 'yoga',
  date: '2026-11-18',
  start: 540,       // 09:00
  end: 600,         // 10:00
  quantity: 2,     // заети места/единици
  customer: 'Иван Петров'
}
```

Часовете са цели минути от началото на деня. Интервалите са `[start, end)`: краят не е включен, затова 09:00–10:00 и 10:00–11:00 могат да следват един след друг. При редактиране текущата резервация се изключва от проверката. При отказ тя се премахва от масива и капацитетът се освобождава.

## Добавяне на нов бизнес

Добавете обект в `src/data/businesses.js`. Основната логика и компонентите остават общи:

```js
{
  id: 'rental', name: 'Велосипеди', type: 'Наем', icon: '◉',
  description: 'Изберете време за разходка.', resourceLabel: 'Велосипед',
  step: 30, durations: [30, 60, 120],
  hours: { 1: [[540, 1080]], 2: [[540, 1080]], 6: [[600, 1080]] },
  resources: [{ id: 'city-bike', name: 'Градски велосипеди', capacity: 5 }]
}
```

Правила за конфигурация: уникални business/resource идентификатори, положителен целочислен капацитет; `step` е положително цяло число, което дели 1440; часовете и продължителностите са кратни на `step`; работните интервали са подредени, без припокриване, в рамките 0–1440. Дните са 0 (неделя) до 6 (събота). Липсващ ден означава почивен ден. Конфигурациите се редактират от разработчика, не от посетителя.

## Оптимизация и алгоритъм

1. **Map индекс:** ключът съдържа бизнес, ресурс и дата. Изграждането е O(N) за N резервации. Прегледът използва само k записа за избрания ресурс и ден.
2. **Масив на разликите:** при начало добавяме заетите места, при край ги изваждаме. С натрупване получаваме заетостта за всяка времева стъпка. Това е O(k + T), където T = 1440 / step (например 48 при 30 минути).
3. **Свободен капацитет:** от капацитета изваждаме максималната заетост в избрания интервал. Не събираме резервации, които не се застъпват една с друга.
4. **Слотове:** за S възможни начала и продължителност D стъпки проверката струва O(S × D). Профилът се използва повторно за всички начала. Не създаваме графици за всички ресурси и всички дни наведнъж.
5. **React:** `useMemo` пази индекса, профила, слотовете и дневния списък; `memo` пази мрежата от излишни рендери. Данните се обновяват с нов масив, вместо чрез директна промяна.

При промяна на резервация индексът се изгражда отново O(N), а localStorage сериализира всички записи O(N). Началното валидиране на записаните данни може да достигне O(N²). Това е съзнателен компромис за разбираем учебен код, не обещание за неограничена производителност. При реален голям продукт са нужни сървър, индексирана база, странициране и транзакции.

## Обхват и ограничения

Приложението е демонстрация със симулирани данни. Няма сървър, вход в профил, плащания или синхронизация между устройства/браузърни раздели. GitHub съхранява кода и примерните данни; направените резервации се пазят само в съответния браузър. Не използвайте реални медицински или други чувствителни данни.

Поддържа се един ресурс на резервация и интервали в рамките на деня. Часовете са локален календар, без преобразуване между часови зони. Многодневни наеми, специални празнични графици и едновременно резервиране на няколко различни ресурса изискват разширение. Google Fonts е по избор: при липса на интернет се използва системен шрифт.

## Тъмен режим

Приложението започва с тъмна тема. Бутонът „Светъл режим“ / „Тъмен режим“ в горната лента превключва цветовете и запазва избора в браузъра. Логиката е в `src/components/ThemeToggle.jsx`, а цветовете — в края на `src/styles.css` под `[data-theme="dark"]`.
